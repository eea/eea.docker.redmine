# Redmine 6.1.3 → 6.1.5 upgrade

## Base image and dependencies

The Dockerfile and both Compose build services now default to
`redmine:6.1.5@sha256:f3e8567ccd59703c92f95e6da2e85c72b764cfa0f08b622e6b0a367b4da64b62`.
The Ruby build guard remains `3.4.`. Redmine 6.1.5 pins Rails to `7.2.4` and
supports Ruby `>= 3.2, < 3.5`.

Sources checked on 2026-10-06:

- [Redmine 6.1 changelog](https://www.redmine.org/projects/redmine/wiki/Changelog_6_1)
- [6.1.5 Gemfile](https://raw.githubusercontent.com/redmine/redmine/6.1.5/Gemfile)
- [Docker official image tags](https://hub.docker.com/_/redmine/tags)
- [Official image publication manifest](https://raw.githubusercontent.com/docker-library/official-images/master/library/redmine)

The base image is pinned to the **multi-platform OCI index digest** from the
user-provided output of `docker buildx imagetools inspect redmine:6.1.5`,
captured on 2026-10-06. The index includes amd64, arm64 and the other published
platforms, so Docker still selects the appropriate architecture. The Dockerfile,
both Compose build arguments and README example use the same pin.

For future upgrades, resolve the new index with
`docker buildx imagetools inspect redmine:<version>` and update these references
together. Use the top-level `Digest:` value, rather than a per-platform manifest
or attestation digest.

## Patch and override decisions

No production patch or override was removed. Review used the 6.1.4/6.1.5
changelog, the 6.1.5 dependency declarations, local patch sources and available
upstream `6.1-stable` sources. This is a static review, not proof of runtime
compatibility; exact-tag source retrieval and container tests remain incomplete.

| Area | Decision and reason |
|---|---|
| Member/project performance patches | Retain. Upstream `Member.sorted`, `Member#any_inherited_role?`, `Project#principals_by_role` and `ProjectsController#settings` still have the query paths these patches address. The child-project permission fix does not replace these read-path optimizations. |
| Activity author preload | Retain. The upstream activity fetcher still collects and sorts events without the bulk author preload. |
| Time-entry patches | Retain. Upstream `TimeEntryQuery#results_scope` does not add the custom-value preload. No replacement for the other local time-entry patches was identified in the maintenance changelog. |
| Wiki links and tracker classes | Retain. The available upstream wiki parser still uses local `url_for`; Taskman routes through `main_app` inside engines. Tracker-name CSS classes are deployment-specific. |
| Agile, Helpdesk, Contacts, Resources and Deals patches | Retain. These target plugin code, not Redmine core. Paid plugin sources are provided separately and were unavailable for runtime comparison here. Retest with the deployed addon versions. |
| Banner/Helpdesk/Mermaid/sprint view overrides | Retain. These are plugin routing, counting and rendering fixes. No corresponding core fix was identified. |
| A1 CSS/JS, branding and compatibility assets | Retain. They provide Taskman-specific behavior. Upstream SVG path caching does not replace these assets. Visual validation still requires A1 and a running instance. |
| RedmineUP duplicate named route guard | Retained during the core upgrade; subsequently removed in the [CRM 4.5.0 plugin upgrade](2026-10-redmineup-upgrade.md), whose routes no longer duplicate the shared gem route. |
| Gem overrides | Retain. They supply runtime integrations and dependencies for addons mounted after build. Rails is not overridden, so the new upstream pin is preserved. Explicit `mysql2` and `with_advisory_lock` remain necessary because Gemfile composition runs before the build creates `database.yml`. |
| Custom migrations and migration retry wrapper | Retain. The upstream plugin-migration cache fix handles repeated migrations in one process; Taskman's wrapper launches separate rake processes and retries concurrent migration locks. |
| Test compatibility initializer | Remove only the no-op advisory-lock fallback. The real gem is an image dependency and tests should expose missing locking support. Keep plugin-specific test shims pending full addon tests. |

The patch inventory previously described `WIKI_LINKS_MAIN_APP` as disabled,
although the initializer defaults it to on. Documentation now reflects the code;
the toggle and production behavior have not changed.

## Test changes

- EEA plugin tests now require Redmine's own test helper, including transactional
  fixtures, Mocha and Settings cache cleanup.
- Agile tests call the patched `board_issue_statuses` method on one stubbed query
  and compare complete status IDs. They also cover empty scopes and scopes with
  selected/ordered columns. The old tests duplicated SQL instead of exercising
  the patch, compared only counts and used wall-clock thresholds on tiny fixtures.
- `ci-runtime` clears inherited `BUNDLE_WITHOUT` so Redmine's test dependencies
  remain available. Startup now honors an explicitly empty `BUNDLE_WITHOUT`
  when writing local Bundler settings, rather than excluding the test group again.
- Jenkins checks actual Redmine, Rails and Ruby versions and the real advisory
  lock API after preparing the test database, before running the existing suites.

## Validation and rollout

Run against disposable test data and the same addon versions as production:

```bash
REDMINE_BUILD_TARGET=ci-runtime docker compose -f test/docker-compose.yml up -d --build
docker compose -f test/docker-compose.yml exec -T redmine bash -lc \
  'START_SERVER=0 START_CRON=0 START_SOLID_QUEUE=0 RUN_DB_MIGRATE=1 RUN_PLUGIN_MIGRATE=auto ASSETS_PRECOMPILE=1 ASSETS_PRECOMPILE_FORCE=1 RAILS_ENV=test /start_redmine.sh'
docker compose -f test/docker-compose.yml exec -T redmine bundle exec rails runner -e test \
  'puts "Redmine=#{Redmine::VERSION} Rails=#{Rails.version} Ruby=#{RUBY_VERSION}"'
docker compose -f test/docker-compose.yml exec -T redmine bundle exec rake redmine:plugins:test NAME=zzzz_eea_patches
docker compose -f test/docker-compose.yml exec -T redmine bundle exec rake redmine:plugins:test
docker compose -f test/docker-compose.yml exec -T redmine bundle exec rake test
docker compose -f test/docker-compose.yml exec -T redmine bundle exec rake test:system
THEME_AUDIT_BASE_URL=http://127.0.0.1:3000 bash test/run_theme_backports_audit.sh
```

The theme audit requires Playwright/Chromium, A1 selected, populated projects and
issues, the expected custom field and suitable test login credentials. The addon
sync needs the configured share credentials or local addon seed directories.

Before rollout, back up the database, attachments and addon volume. Test migrations
on a restored production backup, then use one migration container with
`RUN_DB_MIGRATE=1`, `RUN_PLUGIN_MIGRATE=auto` and forced asset precompilation.
Start web/jobs containers with the same new image and `RUN_DB_MIGRATE=0`.
Smoke-test login, permissions/REST visibility, issue editing, project members,
activity, time entries, plugin boards, wiki links and job processing with the
actual production patch toggles. Roll back with the old image and pre-upgrade
backup together; do not restore the old database after a successful upgrade.

Local checks passed:

- Syntax: 51 Ruby files, 24 shell scripts, two JavaScript files, all configuration
  YAML files and the 17 Jenkins shell blocks.
- Compose validation: default stack, amd64 overlay and EEA plugin overlay.
- Isolated Gemfile composition: Rails/minitest constraints retained, gem
  overrides deduplicated and repeated composition produced identical output.
- Isolated A1 installation: branding assets copied correctly and repeated
  application retained one managed CSS/JS block and the original theme content.
- Bundler configuration: startup includes test groups for CI while preserving
  production exclusions, including when `BUNDLE_WITHOUT` is unset.
- `git diff --check`.

Docker integration was activated in WSL, but the session sandbox still blocks
Docker socket and network access. Image build, migrations, Rails and plugin
suites, browser tests and visual audit have **not** been run here.
