# Banner 0.3.5 → Seraph3000 0.5.3

## Source and compatibility

The image installs `redmine_banner` from
`https://github.com/seraph3000/redmine_banner.git`, tag `v0.5.3`, instead of
Agileware's `0.3.5`. The clean local checkout matches tag commit
`c9dc8d29605883e1fbe5792e4319864a83fd5057`.
The plugin declares Redmine >= 5.0 and its README reports support for Redmine
6.1. This covers Taskman's Redmine 6.1.5 version; it is not a runtime test of
Taskman's Ruby 3.4 / Rails 7.2.4 combination.

Sources: [plugin registration](https://github.com/seraph3000/redmine_banner/blob/v0.5.3/init.rb),
[README](https://github.com/seraph3000/redmine_banner/blob/v0.5.3/README.md).

The fork has no Gemfile and removed the inherited obsolete test suite.
It adds role-based banners, force display, macros and popups, and includes
external-link filtering and session-based project banner hiding.

## Overrides

Do not retain the complete 0.3.5 partials: they would overwrite the new UI and
its security fixes. Both local partials were replaced with the v0.5.3 originals;
only four route expressions were changed to named `main_app` helpers:

- Global edit: `main_app.global_banner_index_path`.
- Global hide: `main_app.off_banner_index_path`.
- Project edit: `main_app.project_banner_index_path(@project, role_id: banner.role_id)`.
- Project hide: `main_app.project_banner_off_project_banner_index_path(@project, role_id: banner.role_id)`.

The upstream partials still use controller hashes / `url_for` which resolve
relative to an engine (such as AI Helper). Keep these adapted overrides and the
Dockerfile copies. The old global edit controller string `main_app/global_banner`
and synthetic ID check have been replaced by the collection route defined by
the fork. Role IDs, macro expansion, popup content, SVG icons, safe external URLs
and session-hide behavior remain as upstream. No other Banner patch was found.

## Migrations and rollout

Relative to Agileware 0.3.5, migrations 006–008 add `role_id` and a project/role
index, `force_display`, `popup_enabled` and `popup_content` to `banners`.
Keep existing Banner data and settings; do not run the uninstall migration
(`VERSION=0`) to switch forks.

Back up the database, build the new image, then use the existing migration
container with `RUN_DB_MIGRATE=1`, `RUN_PLUGIN_MIGRATE=auto` and forced asset
precompilation before starting web/jobs containers from that image.
Install into a clean plugin directory: the fork removed files and changed the
layout. A mounted addon copy of `redmine_banner` takes precedence at startup;
update it through the normal addon workflow, or remove that managed copy if
using the image plugin. Move any backup outside `plugins/`.

Jenkins checks that the loaded Banner version is exactly `0.5.3`.
Smoke-test global and project banners on ordinary Redmine and AI Helper pages:
edit and session hide, role-specific selection/editing, force display, macro and
popup rendering, external links, and anonymous/non-admin access. Confirm that
hiding a project banner does not permanently disable it for other users.
