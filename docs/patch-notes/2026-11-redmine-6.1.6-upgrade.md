# Redmine 6.1.5 → 6.1.6 upgrade

## Motivation

The Ruby advisory published 2026-11-18 reports multiple vulnerabilities in
Regexp and String case conversion with a public remote-code-execution proof of
concept. Ruby 3.4.0 through 3.4.12 are affected; the fix ships in Ruby 3.4.13
(3.3.14 and 4.0.10 for the other supported lines). Taskman's 6.1.5 base image
bundles an unpatched 3.4.x interpreter, so the next Taskman upgrade must move
to a base built on Ruby 3.4.13 or newer.

Redmine 6.1.6 (2026-11-01) is the first 6.1 release whose official Docker
image is built on the patched Ruby line, and it also fixes five Redmine
security defects:

- Defect #44657: ReDoS in wiki macro argument parsing
- Defect #44682: Reflected XSS in `attachments#edit_all` (unvalidated `back_url`)
- Defect #44683: `validate_back_url` accepts URLs that browsers resolve to another host
- Defect #44625: OAuth token scope ignored in `Project.allowed_to_condition`
- Defect #44644: OAuth token scopes bypassed when creating projects

Other notable 6.1.6 changes: sessions and autologin tokens are invalidated
when an email address is changed or deleted (#44578), OAuth errors for
inactive users (#44654), and a browser freeze on pages with thousands of
sortable items (#44372). No database layout changes and no Rails version
change are reported for this release.

## Base image and dependencies

The Dockerfile and both Compose build services now default to
`redmine:6.1.6@sha256:5f5ceb01f68aa45e3bd66606af7a07ec1919b6ff47ad387815f29ee29e2ce1ab`.
The Ruby build guard is tightened from `3.4.` to `3.4.13`, so the build fails
if the base ever drifts back to an unpatched interpreter. The Jenkins
"Verify runtime versions" stage asserts the same minimum.

Verified on 2026-11-20:

- `docker run --rm redmine:6.1.6 ruby -v` reports
  `ruby 3.4.13 (2026-11-19 revision 48857d6f2e) +PRISM [x86_64-linux]`.
- The [6.1.6 Gemfile](https://raw.githubusercontent.com/redmine/redmine/6.1.6/Gemfile)
  keeps `ruby '>= 3.2.0', '< 3.5.0'` and pins Rails to `7.2.4`, unchanged
  from 6.1.5, so the Jenkins Rails assertion and the existing gem overrides
  remain valid.

Sources checked on 2026-11-20:

- [Redmine 6.1 changelog](https://www.redmine.org/projects/redmine/wiki/Changelog_6_1)
- [6.1.6 Gemfile](https://raw.githubusercontent.com/redmine/redmine/6.1.6/Gemfile)
- [Docker official image tags](https://hub.docker.com/_/redmine/tags)
- `docker buildx imagetools inspect redmine:6.1.6` (image built 2026-11-19
  from `ruby:3.4-slim-trixie`)

As before, the base is pinned to the **multi-platform OCI index digest**
(top-level `Digest:` from `docker buildx imagetools inspect`), not a
per-platform manifest or attestation digest. The Dockerfile, both Compose
build arguments and the README example use the same pin.

## Patch and override decisions

No production patch or override was removed. This is a static review against
the 6.1.6 changelog; it identifies no core refactoring in the code paths
Taskman patches (member/project query read paths, activity fetching,
time-entry queries, wiki links, plugin engines), so the
[6.1.5 decision table](2026-10-redmine-6.1.5-upgrade.md) remains in force.
The 6.1.6 fixes are localized to authentication, OAuth scope checks, URL
validation, wiki macro parsing and list rendering. Exact-tag source
retrieval and container tests remain to be completed in CI.

| Area | Decision and reason |
|---|---|
| Runtime patches (Agile, Helpdesk, Contacts, Resources, time entries, members, activity, wiki) | Retain. No 6.1.6 change touches the patched read paths. Retest with the deployed addon versions in CI. |
| Banner/Helpdesk/Mermaid/sprint view overrides, A1 assets | Retain. Plugin routing/rendering fixes with no corresponding core change in 6.1.6. |
| Gem overrides | Retain. Rails pin unchanged (7.2.4); `mysql2` and `with_advisory_lock` are still required before `database.yml` exists at composition time. |
| Custom migrations and migration retry wrapper | Retain. No 6.1.6 database layout changes reported, so the existing migrate container flow is unchanged. |

## Test changes

- Jenkins "Verify runtime versions" now expects Redmine `6.1.6`,
  `Ruby 3.4.13.x` and AI Helper `3.13.1` (delivered with this upgrade per
  #309624, see the AI Helper 3.13.1 upgrade notes); the Rails `7.2.4`
  expectation and the remaining addon version expectations (Banner 0.5.3,
  agile 1.7.0, checklists 4.1.0, contacts_helpdesk 4.3.1, contacts 4.5.0,
  reporter 2.1.0, zenedit 3.1.0, resources 2.1.0, RedmineUP gem >= 1.1.12)
  are unchanged in this branch. The latest RedmineUP plugin releases are
  not part of this rollout (no new archives); they remain a candidate for
  a follow-up release.

## Validation and rollout

Run against disposable test data and the same addon versions as production:

```bash
REDMINE_BUILD_TARGET=ci-runtime docker compose -f test/docker-compose.yml up -d --build
docker compose -f test/docker-compose.yml exec -T redmine bash -lc \
  'START_SERVER=0 START_CRON=0 START_SOLID_QUEUE=0 RUN_DB_MIGRATE=1 RUN_PLUGIN_MIGRATE=auto ASSETS_PRECOMPILE=1 ASSETS_PRECOMPILE_FORCE=1 RAILS_ENV=test /start_redmine.sh'
docker compose -f test/docker-compose.yml exec -T redmine bundle exec rails runner -e test \
  'puts "Redmine=#{Redmine::VERSION} Rails=#{Rails.version} Ruby=#{RUBY_VERSION}"'
docker compose -f test/docker-compose.yml exec -T redmine bundle exec rake redmine:plugins:test NAME=zzzz_eea_patches
docker compose -f test/docker-compose.yml exec -T redmine bundle exec rake redmine:plugins:test
docker compose -f test/docker-compose.yml exec -T redmine bundle exec rake test
docker compose -f test/docker-compose.yml exec -T redmine bundle exec rake test:system
THEME_AUDIT_BASE_URL=http://127.0.0.1:3000 bash test/run_theme_backports_audit.sh
```

Rollout follows the 6.1.5 procedure: back up the database, attachments and
addon volume; test migrations on a restored production backup; run one
migration container with `RUN_DB_MIGRATE=1`, `RUN_PLUGIN_MIGRATE=auto` and
forced asset precompilation; start web/jobs with the new image and
`RUN_DB_MIGRATE=0`; smoke-test login, permissions/REST visibility, issue
editing, project members, activity, time entries, plugin boards, wiki links
and job processing. Roll back with the old image and pre-upgrade backup
together; do not restore the old database after a successful upgrade.
